# Windows / WSL 局域网访问

在 Windows 项目目录执行：

```powershell
node start-wsl.mjs --no-browser
```

该命令确认本机工作台可用，必要时手动启动 WSL 内的查看器，然后为当前已连接的物理私网 IPv4 网卡建立只读转发。终端打印本机 URL 和实际局域网 URL。用电脑或同一子网的手机打开打印出的局域网地址；不要把 `127.0.0.1` 当作手机访问电脑的地址。

命令可以重复执行：已有的兼容查看器与 LAN 转发会复用，避免重复监听。启动不注册开机任务、不设置端口代理、不修改网络 profile 或防火墙。浏览器由使用者打开，Codex 应通过浏览器工具打开或复用页面；`--no-browser` 表明启动命令不会通过 shell 操作浏览器。

## 访问范围

WSL 主服务继续只监听 `127.0.0.1`，保留原 Host 与日志路径保护。Windows 转发仅监听检测到的物理 RFC1918 地址，接受同一实际子网的 IPv4 来源及对应数字 Host，固定转发到本机 `127.0.0.1` 的同一端口。不监听所有地址，不接受公网源、其他 Host、绝对形式代理地址、CONNECT、Upgrade、写方法或请求体，也不向上游传播 Cookie、Authorization 或 Forwarded 凭据。

页面和 HTTP 接口仍只读。局域网界面会展示已接入项目的状态与日志，因此仅用于受信私网，不配置公网映射。当前实现支持 IPv4；手机应与电脑在同一个子网。主机 HTTP 检查不能替代真实手机或路由器隔离检查。

若系统防火墙阻止外部设备连接，应由具有权限的使用者检查并添加仅允许所需端口、当前本地接口和本地子网的规则；本工具不会关闭防火墙或扩大整个网络权限，也不会自行弹出提权窗口。不要因页面在电脑上可访问就把手机验收写成通过。

## 本机配置

端口读取忽略的 `config.json`。本机默认 WSL 为 `Ubuntu-24.04`，普通用户 `qicore-qa`，Node 为 `/home/qicore-qa/.local/node/bin/node`。需要其他配置时可在同一文件加入：

```json
{
  "port": 4399,
  "wsl": {
    "distro": "Ubuntu-24.04",
    "user": "your-user",
    "node": "/home/your-user/.local/node/bin/node"
  },
  "runsRoot": "/home/your-user/.local/state/wsl-progress/runs",
  "sources": []
}
```

手动启动状态记录在忽略的 `.local/lan-session.json`。记录包含进程身份和所有权，不是任务调度器或资源锁；异常或不认识的记录不会被覆盖。

## 停止

```powershell
node start-wsl.mjs --stop
```

停止时只处理该启动器记录且重新核对身份成功的 LAN 转发。已有共享后端不归本启动器所有时会保留。只有它亲自启动的后端、进程身份仍一致且没有执行或等待记录时，才会停止该后端。记录不可读或尚有任务时保留服务，返回明确原因；从不全局关闭 WSL。

已存在的交互终端和其他项目进程不在本命令的清理范围内。若界面仍被其他任务使用，结束某个业务验收任务并不意味着应该关闭共享查看器。
